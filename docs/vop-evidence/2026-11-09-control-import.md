# VC 管控资料导入验证（2026-11-09）

## 数据来源与范围

核对 VOP 公开文档中 SalesVopService 的 queryConsignmentBarcodeListingInfo、VendorProductService 的 ProductSkuInfo / ProductSpuInfo，以及 VendorProductQueryService 的 SkuBaseInfo，未发现可直接对应 VC「管控问题类型」「最后一次下架原因」的字段。此结论限于已核对的公开商品接口，不排除另行申请的业务接口。

参考：[官方条码上下架查询](https://vop.vip.com/home#/api/method/detail/com.vip.somp.sales.backend.service.SalesVopService-1.0.0/queryConsignmentBarcodeListingInfo)。

用户提供的 VC 原始商品导出表已通过实际应用解析器只读验证：494 条、494 个不同商品 ID / 货号、374 个款号；管控类型有值 0 条，历史下架原因有值 382 条。编号以文本完整读取。未提交原始文件或商品明细到代码库，未将文件导入生产数据库。

本次只实现文件导入，按供应商连接和商品 ID 保存，两个字段保留原意。没有尺码条码的导出记录不能按款号或货号前缀投射到所有尺码。历史下架原因不能推算当前管控状态。

## 实现和验证

- 入口：唯品会接入 → VC 管控资料 → 导入 VC 商品表。先本地预览，确认供应商及北京时间后保存；导入成功后可搜索和分页查看。
- 解析和存储测试覆盖文本长编号、空值、必填列、重复 ID、错误格式、时区、供应商隔离、过滤计数、旧快照跳过、同一时刻冲突以及新空值覆盖。相关单元测试通过。
- 独立的本机 PostgreSQL 数据库完成全部迁移和真实 HTTP 验证：登录、vip.settings 权限、CSRF、严格输入、幂等、审计、冲突回滚、时间先后与保留原始字段。测试数据库运行后删除。
- 时间比较在 PostgreSQL 内完成，规避驱动将带时区时间转换成 JavaScript Date 时偏移的情况；显示时间通过 UTC 文本返回。验证等价时区时间不重复保存、晚一小时的新记录能正常更新。
- 浏览器测试覆盖上传预览不写入、确认保存、搜索和数字格式长编号拒绝。类型检查、相关文件 ESLint 和生产构建通过。
- 同步更新用户手册第 19 章、API 契约及侧栏/页脚共用能力摘要。没有新增 AI 调用，无需更改 AI 注册和计量路径。
