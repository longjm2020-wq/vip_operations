# UI_SPEC · 后台页面与交互

## 1. 总体原则

已确定 React + TypeScript + Vite + Ant Design 6；TanStack Query管理服务器数据，Zustand仅UI状态。桌面后台、中文业务语言、以表格和工作流为主。优先交付商品→库存→采购→入库，经营大屏放后续。

Layout侧栏+顶部用户菜单+面包屑；筛选Form、Table分页、Tabs详情、Drawer快速查看、Modal确认、Tag状态、Statistic少量指标。金额显示两位小数，件数整数，时间用配置业务时区，并明确界面时区。所有重要状态带文字，不能只用颜色。

主内容在桌面可读；窄屏允许表格横向滚动、关键列固定，表单可键盘操作、有标签和校验焦点。查询保留筛选/分页；从详情返回列表保持上下文。第一阶段不做复杂主题/设计系统或全新公共组件框架。

## 3. 登录与权限

用户名+密码表单、登录中/失败状态、退出入口。401跳登录并保留返回位置；403显示无权限，不循环跳转。菜单/按钮按权限展示，真正授权仍在API。用户/角色维护包括分配角色、启停用户、重置密码和查看权限；不能显示密码哈希/会话令牌。

## 4. 商品档案及详情

列表筛选：款号/名称、品类、年份、季节、品牌、状态、供应商。列：图片、款号、名称、品类、年份季节、颜色数、SKU数、吊牌价、供应商、状态、更新时间、操作。没有VOP数据时不展示假平台ID/售价/状态；7日销量等后续列默认隐藏。

新建使用独立Form页面：款号、商品名、品类必填；品牌、年份、季节、吊牌价、默认供应商、主图URL、备注可选。保存主档后进入SKU维护，不要求VOP ID。

原对话四步“基本资料→颜色尺码→SKU→确认”为增强交互；第一阶段可以在详情逐条新增SKU，确保CRUD可用后再评估批量笛卡尔积生成，不能在B02未定时静默合并同色码SKU。

详情顶部：主图、名称、款号、品类/季节、状态、编辑。Tabs：

| Tab | Phase 1内容 |
|---|---|
| 概览 | 基本资料、SKU数、实际/可售/在途库存（真实汇总） |
| SKU | 编码、条码、颜色、尺码、成本、状态，新增/编辑 |
| 库存 | SKU分仓余额及流水入口 |
| 采购 | 关联PO、采购量、已入库、未交和状态 |
| 操作日志 | 当前商品及相关SKU的审计链接，按权限展示 |
| 销售/唯品会信息 | 隐藏或文字“尚未接入”，不伪装正常同步 |

供应商/品牌/品类缺失显示“未填写”；图片为空用占位，不使用虚构商品照片。ACTIVE/STOPPED/ARCHIVED有中文标签。

## 5. SKU库存工作台

筛选：SKU/款号/名称/条码、仓库、品类、供应商、颜色、尺码。默认一行“仓库+SKU”；详情呈现全仓汇总，不把分仓和全仓余额混在一列。

列：商品、款号、SKU、颜色、尺码、仓库、实际、锁定、次品、可售、有效在途、更新时间、操作。phase1风险阈值未确认，不展示虚假的缺货/积压统计；可售为0可明确显示“当前可售为0”，不等同未来销售风险。

SKU Drawer：分仓库存、有效PO明细与预计交货、库存流水链接、生成采购建议入口。无可信销售指标时显示“暂无销售数据，暂不能计算补货量”，提供手工建PO入口。开发fixture模式顶部固定“演示数据，仅用于开发验收”，各指标带来源和时间。

库存调整Modal：SKU、仓库只读或显式选择，变化数量（正负）、原因、备注；展示调整前和预计调整后。确认只调用命令；成功后刷新余额/流水，409或422保留输入并刷新权威库存供核对。不能直接在余额单元格内编辑。

流水页：时间、仓库/SKU、类型、源单号、physical/reserved/damaged变化、变化前后、操作者、备注；默认突出实际变化，同时能展开其余分量。源单号可点到Receipt/Adjustment，不把“预留1件”错误显示成“实际出库1件”。

## 6. 采购建议

筛选SKU/商品、供应商、状态、生成日期。风险筛选待完整阈值确认后启用。列：商品/SKU/颜色/尺码、快照可售/在途、7日销量、日均、覆盖天数、目标天数、系统建议、实际确认量、供应商、状态、来源、生成时间。

生成Drawer：选SKU、明确目标库存天数；结果逐条显示生成/已有建议/跳过原因。已忽略后主动重新生成需填写原因；不自动反复弹窗。

处理Drawer并排展示“生成时快照”与“当前库存”，输入本次采购量；改量原因和忽略原因需填写。接受不直接下正式单。已接受/已修改显示“生成采购单”，要求选择供应商、目标仓库、单价；创建草稿PO后跳转详情。建议0不可接受为0采购，允许忽略。MOQ只显示提示，不擅自强制加量。

第一阶段不出现未实现的“加入采购计划”按钮。不把fixture来源的建议隐藏来源标记；生产不加载fixture。

## 7. 采购单

列表筛选单号、供应商、仓库、状态、日期；列：单号、供应商、仓库、采购员、总数量、已入库、有效在途、总额、预计交货、状态。

详情头包含单号、供应商、目标仓库、采购员、预计交货、备注、状态。明细：SKU/商品/颜色尺码、采购量、单价、金额、累计入库、取消量、未交、来源建议。金额以服务端返回为准。

按钮随状态+权限决定：DRAFT保存/提交/取消；PENDING_CONFIRMATION确认/取消；CONFIRMED创建入库及满足条件时取消；PARTIALLY_RECEIVED继续入库；完成/取消只读。禁止任意状态下拉框直接改状态。确认页面说明“确认后计入有效在途”；取消要求原因，已有入库时解释暂不支持部分关闭。

输入中不自动提交；网络超时保留幂等键，提示查证原单。出现version冲突不覆盖他人修改。

## 8. 到货入库

从PO建立Receipt；目标仓库取PO并只读；默认不把全部剩余量自动当已收到。表格列POItem、SKU、订购量、累计入库、剩余、本次到货、合格、次品、少货。

步骤：保存草稿→确认到货→核对验收→过账。到货成功提示“尚未计入库存”，过账前显示本次合格入库总量、影响仓库、PO剩余量；用户明确点击过账。

B01未解决时有次品/少货显示“异常入库规则待确认，可保存，暂不能过账”。正常部分入库可用，剩余仍在PO。POSTED展示过账时间、操作者及流水链接，不能编辑或再次创建效果；重复请求显示原成功结果。

按钮loading/禁用改善体验，但不得充当幂等保证。超时显示“结果待确认”，沿用原请求键查证；不直接提示失败让用户新建第二张单。

## 9. 基础资料与审计

供应商维护编码/名称/联系人/电话/地址/交期/MOQ/状态；仓库维护编码/名称/地址/状态；使用Form+Table+Drawer。停用仓库有活动库存或单据时展示拒绝原因。

审计按操作者/实体/时间/动作筛选，展示时间、用户、操作、单号、前后字段差异；不展示敏感凭据。关联页的审计入口使用entity筛选，不要求用户手工输入内部ID。

VOP设置第一阶段仅“未接入，待应用认证及权限确认”，不显示“最近同步成功”或活跃授权按钮；不要求输入秘密以完成第一阶段。

## 10. 页面验收

每页验证loading、空列表、输入校验、网络失败、401/403、409和重试；表格筛选/分页与API一致。生产无数据不会出现fixture数字。完成一次真实后端的建档→确认PO→部分/剩余入库→查流水流程，刷新浏览器后结果保持。

Phase 2再启用颜色×尺码矩阵、SKU销量、退货与完整风险工作台；矩阵需要区分“没有该SKU”和“SKU数量为0”，不能都显示0。
