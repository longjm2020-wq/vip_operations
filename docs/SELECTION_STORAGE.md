# 选款图片存储与容量验证

修订：2026-09-30

## 已实现的存储路径

- API 复用项目附件的 `AWS_ENDPOINT_URL`、`AWS_S3_BUCKET_NAME`、`AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY`、`AWS_DEFAULT_REGION` 配置。
- 正常上传、洗唛/吊牌图、手机拍图和外部收集表均写入私有对象存储的 `selection-images/` 前缀。数据库存储对象键、类型、字节数与 SHA-256；新上传不保存图片二进制。
- 保持原来的 `/api/v1/style-selections/images/:id` 网址，通过 API 鉴权后读取文件；外部分享仍检查分享有效性及图片归属。没有公开 bucket 或返回存储凭证。
- 每个 API 进程的图片缓存上限为 16 MiB，缓存有效期 60 秒；并发读取同一对象合并请求。每次请求仍先检查权限和数据库记录，内部图片继续使用 ETag 条件请求。
- 当前图片内容仍经 API 转发，尚未启用浏览器直传、CDN 或缩略图。这些网络开销仍应纳入线上容量测试。

## 历史迁移

部署时先执行 026 数据库迁移；API 启动 10 秒后，每批处理 5 张，单张顺序复制，下载核对字节数及 SHA-256 后才设置对象引用。成功批次间隔 1 秒，失败后等待 60 秒再重试。对象键固定，可安全重启继续。

历史数据库二进制保留用于恢复。对象存储异常时历史图片可回退该副本；新图片上传失败会返回 503，不静默转存数据库。数据库磁盘占用不会因此立即下降。暂未执行数据库旧副本清理或 VACUUM FULL。

API 日志中的 `selection-image-migration` 事件提供 `migrated` 与 `remaining`；`remaining:0` 表示当次扫描已完成。将 `SELECTION_IMAGE_MIGRATION=off` 并重新部署可暂停后台复制，不会关闭图片读取或新上传。

数据库只读核对：

```sql
SELECT count(*) AS total,
 count(*) FILTER (WHERE storage_key IS NULL) AS pending,
 count(*) FILTER (WHERE storage_verified_at IS NOT NULL) AS verified_legacy,
 count(*) FILTER (WHERE content IS NOT NULL) AS retained_copies,
 coalesce(sum(byte_size),0) AS image_bytes
FROM style_selection_images;
```

回滚必须使用支持对象存储的版本。已有新图片的 `content` 为 NULL，不能直接回滚到只认识数据库二进制的旧版本。暂停迁移与回滚代码是不同操作。

## 100 用户隔离压测

运行 `SELECTION_LOAD_TEST=1 npm run test:integration`（PowerShell 先设置 `$env:SELECTION_LOAD_TEST='1'`）。脚本拒绝连接非本地地址或非 `vip_erp_test_<时间戳>` 数据库。S3 使用本地协议测试服务，绝不访问生产 bucket。

2026-09-30 测试环境：12 逻辑处理器、约 15.8 GB 内存的本地电脑，Node API、PostgreSQL、本地 S3 测试服务运行在同机。100 个独立用户会话、1515 条款式；30 个用户周期保存，10 个用户周期上传约 300 KB 图片，所有用户读取图片及协作状态。两种模式均先检查版本，变化时才刷新。设置 `SELECTION_LOAD_MODE=legacy` 测试旧版逐页全量刷新，默认模式测试增量同步。各轮使用独立的新建数据库。

## 增量同步协议

主表保留 10 秒版本检查。版本变化时，`POST /api/v1/style-selections/sync` 提交已保存记录的版本标记，服务端在同一个 Repeatable Read 快照内返回全局版本、筛选排序后的 ID/版本索引以及新增或修改的记录。前端依照索引合并记录、删除失效行并更新顺序，保留未修改记录引用；未保存编辑仍由现有页面逻辑保留。首屏没有版本标记，需要完整快照；列筛选、导出与跨页操作仍使用完整资料，尚未改为服务端分页。

相同的在途同步请求合并数据库读取、字段转换和 JSON 序列化，完成后立即释放，不缓存已完成快照。数据库事务结束后每批转换 100 行，再将执行机会让给其他请求，减少整表转换长时间占用事件循环。每个请求独立保留 requestId，响应标记 private/no-store。接口仍检查登录、选款读取权限和 CSRF；所有具备选款读取权限的内部用户拥有相同资料范围。若未来增加行级数据权限，必须将权限范围加入合并键和查询条件。旧 API 尚未部署该端点时，仅 404/405 回退逐页读取，服务错误不会触发额外全量请求。

### 响应转换优化复测（2026-09-30）

相同本地负载再次运行 121 秒，100 用户、1515 行，错误 0，响应正文 576.28 MiB。同步请求 658 次，P95 从上一轮 2456 ms 降至 800 ms；保存 180 次，P95 从 641 ms 降至 533 ms。图片读取 P95 为 563 ms、在线状态写入 782 ms；在线状态读取从 107 ms 升至 254 ms，图片上传从 263 ms 升至 362 ms。各轮请求节奏受响应时间影响，存在运行波动，不能解读为所有操作均加速。此变更不改变用户操作、权限或业务规则，因此不新增操作手册说明。

### 云端隔离验证完成（2026-09-30）

在空白环境 `load-test-20260930` 创建独立 API、PostgreSQL 18.6、私有测试 bucket 和独立压测客户端。全部使用合成用户、款式和图片，没有接入生产数据库、生产 bucket 或唯品会。业务代码与生产 `b284945` 一致，测试脚本版本为 `7b91258`。API 与数据库均为 US West 单实例，资源上限为 24 vCPU / 24 GB；这是弹性上限，不是本次实际用量。数据库连接上限为 100，与生产此前核对的 500 不同。

100 个独立会话、1515 条款式持续运行 902 秒：所有用户约每 2 秒读取协作状态、每 10 秒检查版本并按需同步及读取约 300 KB 图片；30 人每 20 秒保存，10 人每 30 秒上传。闭环负载的实际频率受响应时间影响。完成 80,867 次计量请求，错误 0，响应正文 4088.07 MiB；初始化上传不计入统计。原始指标见 [云端压测结果](performance/2026-09-30-selection-cloud.json)。
