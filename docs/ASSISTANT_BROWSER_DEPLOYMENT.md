# 小序独立浏览器部署

更新日期：2026-11-15。

独立浏览器运行于服务器 Worker，使用现有 Playwright Chromium headless shell；它与用户的本机浏览器、电脑执行器以及唯品会、罗盘的业务登录会话分开。API 提供当前账号的任务和临时接管画面。浏览器能力不等于提供完整云电脑，也不依赖本机安装虚拟机。

## 部署条件

- API 与 Worker 使用同一数据库，先执行迁移 `099_assistant_browser.sql`。它创建每账号默认 profile、任务、加密接管动作和运行状态表，并增加实时语音的固定浏览器目标字段；`098_desktop_device_purpose.sql` 是专用电脑用途功能，两者应按顺序发布。
- API 与 Worker 复用已有的 `COMPASS_MAIL_KEY`，格式为 64 位十六进制 AES-256 密钥，须保持一致。无需新增浏览器服务密钥。浏览器密文通过功能、账号及 profile/任务标识的 AAD 与其他用途隔离。不要在部署日志中输出密钥或存储状态；修改主密钥会使已有密文不可读，不能作为修复单个任务的方式。
- 模型规划通过现有已启用并验证的 OpenRouter 连接，管理条目为 `assistant_browser`。账号必须具备原有小序使用权限；Worker 每次规划及实际输入前重新检查当前权限。
- Dockerfile 在构建阶段安装 Chromium 及系统依赖，运行阶段使用 `USER node`；`/app` 归 `node` 所有，`/ms-playwright` 保持 root 所有并给予运行用户读取、执行权限，避免改变沙箱辅助程序的所有者。浏览器子进程只继承必要系统环境，临时目录按会话隔离，不继承数据库连接、供应商密钥等业务变量。
- 启动明确使用 `chromiumSandbox: true`。Worker 会实际启动和关闭浏览器检查运行条件；宿主不允许 Chromium 沙箱时，功能保持未就绪。不能以自动添加 `--no-sandbox` 作为降级，也不能仅凭镜像中存在浏览器文件就标记就绪。发布后必须核对目标 Railway Worker 上的实际检查结果。

## 网络与会话

每个浏览器通过临时、带认证的本地出站代理访问 HTTP/HTTPS 公网。代理逐连接解析并验证全部 DNS 地址，将实际 socket 固定到已核验的数值 IP；拒绝内网、回环、链路本地、云元数据及非标准端口。Chromium 不允许代理失败后直连，显式取消其默认回环代理绕过，并禁用非代理 UDP、QUIC 和 Service Worker。不要把其他服务的凭据或内部地址放入页面目标。

登录态以 AES-256-GCM 加密保存，包含 Cookie、localStorage 和 IndexedDB；自最后一次成功保存起可复用 30 天，不代表目标网站保证登录 30 天有效。用户清除登录态会立即取消当前任务、增加状态版本并删除密文，迟到的 Worker 保存不能恢复旧会话。状态保存使用参数绑定和所有者/版本/租约校验。接管输入也加密暂存，消费后立即清空载荷；任务结束或过期清理剩余动作。临时截图只通过已认证账号的 `no-store` 接口返回，不进入模型计量日志。

## 运行限制与验收

每个 Worker 最多并行运行 2 个账号的独立浏览器，每账号只允许一个活跃任务。任务从建立起最长 30 分钟，包括排队、暂停和接管时间；自动操作最多 60 步。暂停和需要用户接管时保留同一页面、停止模型规划；恢复后从新观察继续。停止、清除登录态、租约失效或进程中断会关闭浏览器，不自动重放点击或重新发起付费规划。

部署验收应分别核对：浏览器实际沙箱启动、Worker 心跳、无配置不回退本机、公开网页实际加载、每账号会话隔离、同一画面只消费一次接管输入、暂停/停止期间迟到结果不执行，以及新 `assistant_browser` 用量行的实际回执。模型验证、浏览器就绪和目标网站登录是不同状态；不能以其中一项成功替代其他项。
