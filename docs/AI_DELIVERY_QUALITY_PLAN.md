# 小序工作台作品交付与官网质量对标规划

2026-11-21 · 产品与工程方案 · 现状基于 GitHub main 的 `58e70c4`。

以用户从工作台输入需求、收到作品、打开、编辑或下载的完整过程为验收范围。本方案中的“官网”首先指用户截图里的 AgentAI 网页产品。每项结论都要写明官网入口、模式、型号、测试日期与支持范围。现阶段已有单个 HTML 文件的线上播放验证，五类作品的官网对比均待建立。

## 用户拿到什么

一个输入框接受目标、附件和交付格式。例如「用这组衬衫照片做一张竖版主图、一条短视频和一份上新 PPT」。小序复述必要规格，按作品类型找到具备相应权限和输入能力的服务。若用户明确选择型号、尺寸、时长或文件格式，提交前检查其支持情况。收费操作沿用各入口已有的报价和确认规则。

每件作品有独立卡片，包含文件名、版本、预览或运行入口、下载和实际检查结果。聊天、作品库与下载均引用同一份已保存的原件。修改时建立新版本，重新检查受影响的内容。复合任务可先交付已通过的作品，仍在制作或需要修改的部分单独列出。图片可查看原尺寸，视频可拖动播放，HTML 可切换源码和预览，Office 文件可逐页或逐表检查，软件可试用并下载工程。

## 各类作品的目标与验收

| 作品 | 当前实现 | 计划交付 | 判定依据与首个验收案例 |

音频沿用现有独立语音制作和音色授权。加入对标时按相同文稿、音色和速度检查读音、漏字、停顿、削波和下载格式。新增作品类型沿用上表方法，先定义原件、官网样本和检查标准，再纳入发布范围。

## 怎样认定达到官网水平

**逐件检查。** 一次生成成功回执说明供应商完成了任务。网站接着取得原件，核对实际文件类型和规格，打开、解码或构建，并实测用户要求的关键功能。硬性要求必须全部通过。缺文件、截断、关键按钮失效、计算结果错误、软件起不来，均记录原因并进入修复或待核验。已保存的原件、版本和失败证据可回看。

**同条件生成。** 每个基准案例保存原始提示词、授权参考素材及其指纹、期望格式、必需内容、明确允许的差异。记录双方可见的型号、输入模式、实际发送参数、参考图预处理、输出预算及所有试次。官网隐藏的参数记作未知。官网找不到对应模式或拿不到原件时，记录为“独立功能已验收”或“待取得官网样本”。单张截图只用于设计对照。上一轮界面显示的 14,626 字与本站的 token 限制使用不同计量单位。

**同源预览。** 保留同一原件分别在工作台和合适的参考程序中运行的结果。图片比较下载文件与预览缩放，视频核对音轨与播放，网页核对按钮和画面状态变化，文档与 Office 兼容程序的排版比对。先定位差异来自生成、转换、预览还是下载，再改对应环节。

**创作品质盲评。** 建议首轮每类挑选至少 5 个代表任务，其中包含常用任务、边界条件和历史失败案例。随机性高的图片、视频、生成式网页每题每端保留 3 次独立生成，计入失败和重做。两名评审隐藏来源、随机左右顺序，按预先约定的内容准确性、需求符合度和该类型专属维度逐项评“本站较好／同档／官网较好”，分歧由第三人裁定。任一关键维度持续落后即记录整改项。首次试跑可以定位差距，只发布在样本内观察到的结果。

**发布结论。** 拟对外标注“与官网同档”时，用独立留出题复评，按作品类型、模式和版本分别汇总。建议以“同档或更好”的任务比例为指标，每个核心维度的单侧 95% 置信下限达到 90%，同时交付硬性要求全部通过。90% 是拟定的盲评发布标准，单件作品的必需属性逐项验收。评测前锁定题集和判据，每题的多次生成先汇总为一个判定，按独立任务数量计算区间。样本不足以判定时保留“已通过功能验收，官网对标待验证”。遇到官方模型更新、供应商换路由、生成器或预览运行方式变化，复测受影响组合。结论标注范围和日期，成本、耗时、成功率另外列出，方便选择。

## 工程实施与发布顺序

| 阶段 | 主要改动 | 进入生产后的验收 |
| --- | --- | --- |
| 1　打通 HTML 全流程并建立比较基准 | 对话团队负责网页文件工具、长源码独立保存和真实参数转发，前端负责代码卡、右栏和原件下载。复用已上线的隔离预览，按支持度选择运行环境。质量负责人用鹈鹕案例跑通对照记录。 | 从正常聊天入口新建作品并重开，验证源文件完整，桌面和窄屏可操作，历史 TXT 仍可播放。记录请求与结果，分别展示功能是否通过及是否已有官网对照。 |
| 2　让工作台直接使用正确的图片、视频流程 | 工作台接入已有 AIGC 任务、资产和归档。按能力目录开放可实际执行的模式，保存发送给供应商的真实素材版本和参数。视频生成与剪辑分别路由。 | 从聊天各完成一次支持的图像、视频任务，核对原件并做同题比较。断线恢复查询原任务号，同一任务重复点击或重启时不会重复收费提交。 |
| 3　补齐 Office 作品的专业交付 | 文档服务分别增加排版、模板、图表、公式及渲染检查；按 DOCX、XLSX、PPTX 分批发布。 | 在新下载的文件上执行回读和逐页检查，核对业务数值、可编辑性和视觉标准，同一模板的官网样本单独盲评。 |
| 4　交付可运行的软件，再扩展其他类型 | 先建立隔离的 Web 工程构建和短期预览服务，再按实际需求增加各系统安装包、音频等交付类别。生成工程在与业务系统分开的环境运行。 | 从源码包在全新环境重建，并从用户入口操作核心流程。每个目标平台分别记录支持、实测通过或待验收。 |

每个阶段复用现有账号权限、任务记录、文件存储及计量。后台为作品保存类型、版本、原件指纹、实际型号或执行工具、可取得的回执与验收证据。用户界面区分“生成中”“正在检查”“可交付”“需修改”和“待核验”。首选重验已有文件或恢复原任务，新增收费生成按现有费用授权执行。调用次数、token、积分、币种和未知金额按供应商回执各自记录。作品基准选用授权或合成素材，原文件存放在受控作品库。

模型和参数选择必须能追溯到发出的请求，按作品类型设置输出预算、分段保存及完整性检查。普通工作台对话与作品正文可以采用不同长度配置。对重要行为保留浏览器实际运行测试。软件试用使用隔离环境。若用户另外要求操作自己的电脑，仍须明确指定设备并沿用现有授权、暂停和接管。各阶段完成后同步模型管理登记、实际用户手册与必要的功能摘要，经 GitHub main 部署 Railway 并验收真实生产入口。
