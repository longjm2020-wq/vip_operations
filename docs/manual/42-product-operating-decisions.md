# 商品经营决策

更新日期：2026-11-17。入口：运营中心 → 唯品会工作区 → 商品档案 → 字段分组栏「经营决策」。规则版本：2026-11-17.2。

## 用途与前提

按款汇总生产采购端、退供清仓端、销售数据端意见，分别给出补货资格和销售状态。允许补货表示具备补货条件，不等于现在需要下单；补多少仍需到库存明细按颜色、尺码核对。经营决策没有自动采购、库存调整或唯品会上下架动作，也不调用 AI 模型、不产生模型用量。

需要已保存、非空且有权查看的商品档案款号。查看沿用商品查看及款号单元格的保护权限；修改还需商品编辑、款号区域编辑及认领规则允许，传送锁定行不能修改。决策反馈为该款的共享业务资料，有权查看该款的人员可见。销售依据额外需要经营分析查看权限，无此权限不会返回销售指标及历史销售判断快照，仍可按权限查看或维护人工反馈。

## 查看与操作

1. 完成商品档案自动保存，再选择「经营决策」。在页面右上角的商品搜索框输入款号、供应商等关键词，或点相机图标查找同款。搜索期间商品档案的列筛选暂停，清除搜索后恢复。点击「清除图片查找」会恢复图片定位前的关键词或列筛选结果。只显示已保存且有权查看的款号。
2. 款号右侧显示商品档案「图片」字段第一张可查看的图片。点击缩略图打开商品档案的图片查看器，可放大、缩小和切换同款图片。缺少图片或没有图片查看权限时显示「—」。可按测试阶段、补货资格、销售状态及经营标签筛选。底部分页固定显示筛选后的总数与页码，默认每页20款，可切换为20、50、100、200、500、1000或5000款。表内还显示判断依据、数据截止和人工反馈人/时间。
3. 点击款号打开侧栏，顶部显示已保存反馈对应的测试阶段、补货资格、销售状态和判断依据。编辑时小序悬浮图标在侧栏遮罩后方。在「生产采购端」直接点选「待确认／允许补货／不允许补货」，选择非待确认选项后勾选对应原因。
4. 在「退供清仓端」可标记压仓库存。选择「品质退供／大货退供／清仓完结」表示明确的停售反馈。采购和退供的说明可展开对应的「补充（选填）」填写，已有说明默认展开。在「销售数据与确认」直接选择「采用规则建议／确认继续销售／确认停售」，人工确认必须填写原因。展开「销售数据端 · 自动判断依据」可核对统计窗口和销售指标。
5. 点击「保存三端反馈」才写入。新提交停售决定会再次确认，保存后显示「已确认停售」和「不允许补货」，不直接下架平台商品。保存成功立即重新判断，并记录操作者、时间、反馈、当时规则结果及报表口径。展开「反馈记录 · 最近20次」可查看人工保存记录。
6. 修改反馈后未保存，关闭会询问是否放弃。恢复为「待确认」、取消压仓标记、撤销停售反馈或改回「采用规则建议」后，也须保存才生效。继续销售前须先撤销退供清仓端的停售反馈。
7. 点击「数据截止」表头旁的「更新判断」图标重新读取最新已完整导入的报表，不启动平台下载；页面打开后每分钟刷新判断。展开「销售数据端 · 自动判断依据」，按权限点击「查看经营分析」或「查看库存与补货数量」，目标页面会直接按该完整款号筛选。

表格上方的经营标签卡片和「经营标签」列筛选提供相同标签。可同时选择多个标签，命中任一标签即显示。列筛选菜单中的「重置」立即清除本列条件，返回第1页，其他列和顶部搜索保留。点击「全部款」也可清除标签筛选。卡片按当前搜索和其他列筛选统计所有分页的款数。同一款可计入多张标签卡片，标签款数相加可能超过「全部款」；无标签的款只计入「全部款」。

自动判断按当前完整报表实时计算，不每分钟新增历史记录。历史中的结果是当时保存快照，可能与今天的判断不同。原表款号变更后不沿用原款人工反馈，显示重新确认提示，旧记录仍保留在历史中。

## 按款号导入和导出反馈

1. 未勾选时，导出当前搜索和筛选命中的所有分页，导入按文件里的款号在同一范围内匹配。勾选款号可进一步缩小范围，支持跨页勾选。
2. 点击「导出反馈」，下载 `商品经营反馈.xlsx`。文件包含款号、补货条件和判断原因、采购补充、压仓标记、停售反馈和退供清仓补充、人工销售确认及原因、反馈版本、档案版本和档案行 ID。只读账号可导出有权查看的反馈。导入每批最多200行，较大的导出文件可分批导入。
3. 可编辑导出的文件，也可打开「导入反馈 → 下载反馈模板」，填写空白 Excel 的款号和反馈。模板无需勾选即可下载。多个补货判断原因用顿号分隔。手工整理文件时可只保留款号和需要更新的反馈列。缺少的列保留原值；空白模板里的补充说明留空也保留原值，带原有版本的文件里清空补充说明可删除对应说明。换补货条件时填写匹配的新原因，或设为「待确认」以清除补货判断原因。
4. 点击「选择 Excel 文件」预览，再点击「确认导入」。以完整款号匹配，忽略字母大小写和首尾空格。同款有多条记录时，请勾选目标记录或沿用导出文件里的档案行 ID。文件须为 `.xlsx`，最大5 MB，修改需相应款号的编辑权限。新增停售反馈仍需勾选确认。超出操作范围、重复行、版本过期或无权限时按预览提示修正。提交后逐行列出结果，临时失败可点击「重试失败行」。已保存的行会重新判断并写入反馈记录。

## 三端规则与优先级

生产采购端人工反馈：供应商有现货、生产周期不超过20天属于允许原因；不满足起订量、停产、生产周期超过20天、换季倒计时不超过30天属于不允许原因。生产周期正好20天归允许原因。这里只保存人工已核对的原因，不根据未接入的供应商系统自动推定。

**人工生效范围**：补货资格和销售状态分别判断。只填写补充说明、保留「待确认」「无停售反馈」或「采用规则建议」，表示该项未给出人工结论。无人工结论时采用销售数据判断。

- **明确停售**：品质退供、大货退供、清仓完结或人工确认停售时，销售状态为「已确认停售」，补货资格为「不允许补货」，优先于采购允许补货和销售数据结果。
- **补货资格**：其余情况下，直接采用生产采购端确认的「允许补货」或「不允许补货」。生产采购端为「待确认」时才看销售数据，数据不足时仍为「待确认」。
- **销售状态**：没有明确停售时，人工确认继续销售或标记压仓库存均显示「继续销售」，否则采用销售数据结果。压仓库存是长期积压、需继续上线消化的库存，可与「高退货率」同时存在。继续销售和压仓标记只决定销售状态，补货资格仍按上一条判断。

## 销售数据判断

以下是销售数据的自动判断。人工已给出结论时，仍显示相应的指标和数据标签，最终状态以人工优先级为准。仅使用当前完整导入的罗盘「款号」维度报表，款号去除首尾空格、忽略字母大小写后完整匹配，不模糊关联、不将款号/货号/条码三份报表相加。售龄取报表截止日记录，缺失时才按首次上架日期计算；不用档案创建日期代替。观察窗口按截止日售龄回推，规则中的第1天包含在统计中。

- **首测，售龄1—10天**：统计首次在售日至报表截止日。有效销量大于零形成销售端允许依据。商详UV≥100且加购率≥8%时标「潜力款」「营销促转化」「待回测」，售龄进入第11天后进入回测。曝光UV、CTR一并展示供判断。
- **首测失败边界**：满10天、记录完整、曝光UV≥2000、商详UV<100、加购率<8%且销量为零时，结合下述库存快照判定。全期每日均显示在售且有可售库存，才标「首测失败」、给出销售端不允许补货并建议停售。已有销量、期未满、曝光不足、仅一个指标达标或缺少商详与加购指标时继续观察。CTR参考阈值5%。
- **回测，售龄11—20天**：只统计第11天起的回测销售。有销量形成允许依据；满第20天、整个回测窗口完整且销量为零时，按下述库存快照核实。全期每日均显示在售且有可售库存，才标「回测失败」、给出销售端不允许补货并建议停售。未满观察期继续观察。
- **观察期，售龄21—30天**：统计第21天起的数据，继续观察销售，不自动判失败或停售。
- **常测，售龄超过30天**：统计截至报表截止日的近30天。有销量时，期间退货率>80%标高退货率并建议人工复核停售，销售端补货资格暂待确认；正好80%不命中。全期零销量时核实每日库存，退货率显示「—」。

**零销量核实**：在上述符合判断时机的测试期内，完整报表确认销量为0，且每天「在售库存」和「可售库存」都大于0时，规则建议停售，销售端判为不允许补货。常测命中时标「在售无销量」。任一天有库存零值或缺失时，标「零销量待核实」，销售端结论待确认。侧栏显示每日同时为正、各自为零及库存缺失的天数；同一天可同时计入两个零值。罗盘提供每日快照，零值时应结合库存变动和上下架记录核实长期缺货或未上线的原因。经营人员可核实后填写人工确认及原因。压仓库存和其他有效人工反馈仍按优先级处理。

CTR=期间累计商详UV÷累计曝光UV；加购率=累计加购UV÷累计商详UV；期间退货率=累计退货件数÷累计销售量。跨日UV未去重，退货率可能超过100%，不表示同一批订单的真实退货概率。缺失单元格不补零，也不拿每日比例的平均值冒充期间比例。

## 数据不足与常见问题

没有完整款号报表、截止日未匹配该款、同款出现多个平台记录、售龄无效、观察期覆盖不足、销量缺失，均不自动给出销售端允许或失败结论。报表截止日距今天超过3天视为过期；当天及未来日期的报表不能用于判断。已有的采购结论、退供清仓反馈、压仓标记和人工销售确认仍分别生效。

「经营分析 → 更新数据」完成后再回本页更新判断。短报表缺少完整观察窗口时需补齐原始来源，不能依靠缺失数据推导零销量。没有经营分析权限时联系管理员授权。

保存冲突表示他人已修改反馈或档案款号/版本变化，当前修改不覆盖服务器结果；先保留需要的文字，再点击「重新读取」并确认放弃草稿，核对后重新提交。读取失败可重试，不能将失败当作没有风险。经营决策入口只适用于商品档案，普通协作表格和选款登记不提供此功能。
